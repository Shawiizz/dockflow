# Docker Registry

import { Callout, Tabs } from 'nextra/components'

A Docker registry stores your images centrally so cluster nodes can pull them independently — on
Swarm as well as on k3s, the `registry` configuration below is identical.

## When to Use

- **Single node**: Not required. Images are transferred via SSH.
- **Multi-node Swarm**: Recommended for large clusters. Without a registry, Dockflow transfers images to each node via SSH (`docker save | ssh | docker load`), which works well for small clusters but becomes slower as the number of nodes or image size grows.
- **Multi-node k3s**: Recommended for the same reason — without a registry, Dockflow imports images into containerd on each node over SSH (`docker save | ssh | k3s ctr images import`, see [Container Engine](/en/configuration/container-engine#k3s-and-containerd)).

## Configuration

Add the following to `.dockflow/config.yml`:

<Tabs items={['GitHub (GHCR)', 'GitLab', 'Docker Hub', 'Self-Hosted']}>
  <Tabs.Tab>
    ```yaml
    registry:
      type: ghcr
      enabled: true
      url: "ghcr.io"
      namespace: "your-org"
      username: "{{ current.env.registry_username }}"
      token: "{{ current.env.registry_token }}"
    ```

    **CI/CD secrets required** (here for `production`):
    - `PRODUCTION_REGISTRY_USERNAME` (GitHub actor)
    - `PRODUCTION_REGISTRY_TOKEN` (GitHub token with `packages:write` scope)
  </Tabs.Tab>

  <Tabs.Tab>
    ```yaml
    registry:
      type: gitlab
      enabled: true
      url: "registry.gitlab.com"
      namespace: "your-group/your-project"
      username: "gitlab-ci-token"
      token: "{{ current.env.registry_token }}"
    ```

    **CI/CD secrets required** (here for `production`):
    - `PRODUCTION_REGISTRY_TOKEN` (set it to `$CI_JOB_TOKEN`, which GitLab CI provides)
  </Tabs.Tab>

  <Tabs.Tab>
    ```yaml
    registry:
      type: dockerhub
      enabled: true
      url: "docker.io"
      namespace: "your-username"
      username: "{{ current.env.registry_username }}"
      password: "{{ current.env.registry_password }}"
    ```

    **CI/CD secrets required** (here for `production`):
    - `PRODUCTION_REGISTRY_USERNAME`
    - `PRODUCTION_REGISTRY_PASSWORD`
  </Tabs.Tab>

  <Tabs.Tab>
    ```yaml
    registry:
      type: custom
      enabled: true
      url: "registry.example.com"
      namespace: "your-team"
      username: "{{ current.env.registry_username }}"
      password: "{{ current.env.registry_password }}"
    ```

    **CI/CD secrets required** (here for `production`):
    - `PRODUCTION_REGISTRY_USERNAME`
    - `PRODUCTION_REGISTRY_PASSWORD`
  </Tabs.Tab>
</Tabs>

<Callout type="info">
  Registry credentials use Nunjucks template syntax. Values from `servers.yml` env vars or CI secrets are available as `current.env.variable_name` (lowercased). A secret is scoped to one environment by its prefix: `PRODUCTION_REGISTRY_PASSWORD` is `current.env.registry_password` when deploying to `production`, and a secret without the prefix never reaches `current.env` (see [Variable Overrides](/en/configuration/servers#variable-overrides)).
</Callout>

## Configuration Reference

| Field | Type | Description | Default |
|-------|------|-------------|---------|
| `type` | `local` \| `dockerhub` \| `ghcr` \| `gitlab` \| `custom` | Registry type (required) | — |
| `enabled` | `boolean` | Enable/disable registry push | `true` |
| `url` | `string` | Registry hostname (required for `custom` type) | — |
| `namespace` | `string` | Organization or username prefix for images | — |
| `username` | `string` | Registry username | — |
| `password` | `string` | Registry password (use template syntax for secrets) | — |
| `token` | `string` | Registry token (alternative to password) | — |
| `additional_tags` | `string[]` | Extra tags to push besides the version tag | — |

## Image Tagging

By default, images are tagged with the deployment version. You can add extra tags that point to the same image:

```yaml
registry:
  type: ghcr
  enabled: true
  url: "ghcr.io"
  namespace: "your-org"
  additional_tags:
    - "latest"
    - "{env}"
```

**Example:** Deploying version `1.2.0` to `production` produces:

```
ghcr.io/your-org/my-app:1.2.0       # main tag (version)
ghcr.io/your-org/my-app:latest      # additional tag
ghcr.io/your-org/my-app:production  # additional tag ({env} replaced)
```

Available variables: `{version}`, `{env}`, `{branch}`, `{sha}`

## How Images Are Pushed

Images are built and pushed from the machine that runs `dockflow deploy` (your laptop or the CI
runner). When `username` is set, Dockflow first runs `docker login` there (`podman login` with
Podman), the password or token on stdin; without a username the registry is pushed to
anonymously. A wrong password stops the deploy at that login, before anything reaches a server.

## How Nodes Pull From a Private Registry

<Tabs items={['Swarm', 'k3s']}>
  <Tabs.Tab>
    Dockflow logs in on the manager (`docker login`) and deploys with `--with-registry-auth`, which
    forwards the encrypted credentials to every worker so they can pull independently. Nothing is
    written to disk on the workers.
  </Tabs.Tab>
  <Tabs.Tab>
    Dockflow applies one Kubernetes image pull Secret, `dockflow-registry`
    (`kubernetes.io/dockerconfigjson`), in the stack's namespace, and every workload references it.
    There is no `docker login` step and no `registries.yaml` to edit on any node — the credentials
    exist only inside that Secret, rotate by re-deploying, and reach no node's filesystem.
  </Tabs.Tab>
</Tabs>

## Troubleshooting

**Authentication failed**: Test the same credentials with `docker login <url>` on the machine that
deploys, and check that `username`/`password` or `token` resolve to real values with
`dockflow validate <env>`.

**Push denied**: Verify write access to the namespace.

**Workers cannot pull (Swarm)**: Ensure all Swarm nodes can reach the registry. For private registries, authenticate on each node.

**Pods stuck `ImagePullBackOff` (k3s)**: Check `dockflow diagnose <env>` for the pull error, and
confirm `registry.enabled: true` so the `dockflow-registry` Secret is actually applied.
