# Compose Support Table

import { Callout } from 'nextra/components'

How Dockflow handles every key of a compose file (`docker-compose.yml` and `accessories.yml`) on Docker Swarm and on k3s. On k3s, each key of the Compose specification has exactly one policy: it is translated to Kubernetes objects, translated with a warning, ignored because nothing corresponds to it, or rejected with an error that says what to use instead. No key is ever dropped silently.

<Callout type="info">
  This page is generated from the key registry of the CLI. After changing the registry, run `bun run scripts/gen-compose-support.ts` in `cli/`; `bun run scripts/gen-compose-support.ts --check` fails when the tables below are out of date.
</Callout>

## Reading the tables

- **Key**: the path of the key in the compose file. `*` stands for any service, volume, network or map key, `[]` for the items of a list (the long syntax of `ports`, `volumes`, `secrets`...).
- **Swarm**: what `docker stack deploy` does with the key: **Supported**, **Ignored** (skipped with a warning) or **Rejected** (the deploy fails).
- **k3s**: what the Kubernetes translation does with the key:

| Outcome | Meaning |
|---|---|
| Translated | Mapped to Kubernetes fields. Details are printed with `--debug`. |
| Translated with warning | Mapped as closely as Kubernetes allows; the deploy prints a warning that says what differs. |
| Ignored | Nothing in Kubernetes corresponds to the key and nothing is lost; the Notes column says why. |
| Ignored with warning | The key has no effect on k3s; the deploy prints a warning. |
| Rejected | `dockflow deploy` and `dockflow validate` stop with an error that names the key and the fix. |

When the outcome depends on the value (for example "Translated; some values are rejected"), the Notes column says which values.

- **Notes**: the Kubernetes target, the values that behave differently, and the `x-dockflow` settings that change the translation.

Run `dockflow validate <env>` to see every warning and error for a project without deploying it.

## Keys that are not in the tables

- **Unknown keys are refused.** A key that is neither in the Compose specification this release follows nor in these tables stops the deploy: it is either a typo (the error suggests the closest known key) or a key added to Compose after the specification date given below, which needs a newer Dockflow.
- **Extension fields** (`x-` keys) are skipped, so they can hold YAML anchors, except `x-dockflow`, which carries the Kubernetes-only settings of a service or a top-level volume. Its keys are listed in the `x-dockflow` reference of the [Kubernetes page](/en/configuration/kubernetes).
- **Traefik labels** (`traefik.*` in `labels` or `deploy.labels`) become routes and middlewares; the [Kubernetes page](/en/configuration/kubernetes) describes how they are translated.
