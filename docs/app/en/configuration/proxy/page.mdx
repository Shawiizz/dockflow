# Automatic HTTPS Proxy

import { Callout, Steps, Tabs } from 'nextra/components'

Dockflow can automatically provision HTTPS certificates and route traffic to your services using [Traefik](https://traefik.io) as a reverse proxy. Add a domain to your config and it works — no Nginx config to write, no Certbot to manage.

<Callout type="info">
  Traefik is deployed as a Docker Swarm service on your manager node. It watches your stack deployments and automatically obtains Let's Encrypt certificates via HTTP challenge.
</Callout>

## Minimal Configuration

```yaml
# .dockflow/config.yml
project_name: "my-app"

proxy:
  enabled: true
  email: admin@example.com
  domains:
    production: my-app.example.com
```

That's it. On the next `dockflow deploy production`, Dockflow will:

1. Deploy Traefik on your manager node (if not already running)
2. Inject Traefik routing labels into your app services
3. Traefik contacts Let's Encrypt and obtains the certificate
4. HTTPS is live, HTTP automatically redirects to HTTPS

## Multiple Environments

```yaml
proxy:
  enabled: true
  email: admin@example.com
  domains:
    production: my-app.example.com
    staging: staging.my-app.example.com
```

Each environment gets its own domain and certificate. Traefik handles renewals automatically.

## All Options

```yaml
proxy:
  enabled: true
  email: admin@example.com        # Required when enabled
  domains:
    production: my-app.example.com
    staging: staging.my-app.example.com
  routes:                          # Optional: services on domains of their own
    - service: admin
      domains:
        production: admin.example.com
      path: /api                   # Optional
      port: 8080                   # Optional
  dashboard:
    enabled: true                  # Optional: expose Traefik dashboard
    domain: traefik.example.com
  trusted_ips:                     # Optional: a CDN or load balancer in front of Traefik
    - 173.245.48.0/20
```

| Field | Type | Description | Default |
|---|---|---|---|
| `enabled` | boolean | Enable Traefik proxy | `false` |
| `email` | string | Email for Let's Encrypt notifications. Required when `acme` is not disabled | — |
| `acme` | boolean | Enable ACME/Let's Encrypt TLS. Set to `false` for HTTP-only mode | `true` |
| `domains` | map | Domain per environment, where every service with `ports:` answers | — |
| `routes` | list | Services routed on domains of their own. See [Routing a Service on Its Own Domain](#routing-a-service-on-its-own-domain) | — |
| `routes[].service` | string | Service of `docker-compose.yml` or `accessories.yml` | — |
| `routes[].domains` | map | Domain per environment. In the others, the service gets no route at all | — |
| `routes[].path` | string | Only the requests whose path starts with this prefix | — |
| `routes[].port` | number | Container port the requests go to | first port of the service |
| `dashboard.enabled` | boolean | Expose the Traefik dashboard | `false` |
| `dashboard.domain` | string | Domain for the dashboard. Required if `dashboard.enabled: true` | — |
| `trusted_ips` | list | Addresses or CIDR ranges whose `X-Forwarded-*` headers Traefik keeps. See [Behind a CDN](#behind-a-cdn) | — |

<Callout type="warning">
  **Dashboard security** — The Traefik dashboard is exposed publicly when enabled. Restrict access with your firewall or add [Traefik middleware](https://doc.traefik.io/traefik/middlewares/http/basicauth/) for basic auth.
</Callout>

## HTTP-Only Mode (no TLS)

Set `acme: false` to run Traefik without HTTPS — useful for internal networks, development environments, or staging setups where you handle TLS termination elsewhere.

```yaml
# .dockflow/config.yml
proxy:
  enabled: true
  acme: false
  domains:
    staging: staging.internal
```

When `acme: false`:
- Port 443 and the HTTPS redirect are disabled — Traefik only listens on port 80
- No Let's Encrypt certificate is requested — `email` is not required
- Routing labels use `entrypoints=web` instead of `websecure`

<Callout type="warning">
  Do not use `acme: false` in production with public traffic. Your app will be served over plain HTTP.
</Callout>

## Behind a CDN

When a CDN or a load balancer sits in front of Traefik, Traefik sees the CDN's address, and the
client's arrives in `X-Forwarded-For`. Traefik drops forwarded headers from senders it does not
trust, so list the CDN's ranges (your CDN publishes them) in `trusted_ips`:

```yaml
# .dockflow/config.yml
proxy:
  enabled: true
  acme: false            # the CDN terminates TLS
  domains:
    production: my-app.example.com
  trusted_ips:
    - 173.245.48.0/20
    - 103.21.244.0/22
    - 2400:cb00::/32
```

Traefik then passes the client's address on in `X-Forwarded-For` to your services.
`trusted_ips` only decides whose headers are believed: it does not stop other addresses from
reaching Traefik (see the warning under [Requirements](#requirements)).

## Requirements

- Ports **80** and **443** must be open and reachable from the internet on your manager node
- Your domain's DNS must point to your manager's IP before deploying
- Your app service must expose a port in `docker-compose.yml` (Traefik reads this to know the container port), or be routed by [`routes`](#routing-a-service-on-its-own-domain)

<Callout type="warning">
  Traefik publishes 80 and 443 through Docker, which writes its own iptables rules: ufw and
  firewalld do not filter them, and neither do they filter the `ports:` of your services. To
  restrict who reaches them (only a CDN's addresses, for instance), add rules to the
  `DOCKER-USER` chain, which Docker evaluates before its own.
</Callout>

## How It Works

<Steps>
### Traefik deployment

On `dockflow deploy`, Dockflow creates a `traefik-public` overlay network and deploys Traefik as a Swarm service on the manager node. Traefik watches the Docker Swarm API for services with `traefik.enable=true` labels.

Traefik answers the internet, so it does not mount the Docker socket. It reads the Swarm API
through a second service of the `traefik` stack,
[docker-socket-proxy](https://github.com/Tecnativa/docker-socket-proxy), which alone mounts the
socket (read-only) and only answers `GET` requests on services, tasks, networks, nodes and
system info, over an internal network that only Traefik joins.

### Label injection

Dockflow automatically injects Traefik routing labels into your app services (any service that has `ports:` defined):

```yaml
# What Dockflow injects automatically
deploy:
  labels:
    - "traefik.enable=true"
    - "traefik.docker.network=traefik-public"
    - "traefik.http.routers.my-app-production-app.rule=Host(`my-app.example.com`)"
    - "traefik.http.routers.my-app-production-app.entrypoints=websecure"
    - "traefik.http.routers.my-app-production-app.tls.certresolver=letsencrypt"
    - "traefik.http.services.my-app-production-app.loadbalancer.server.port=3000"
networks:
  - default
  - traefik-public
```

### Certificate issuance

Traefik performs an HTTP-01 ACME challenge with Let's Encrypt. The certificate is stored in a persistent Docker volume (`traefik-certs`) and renewed automatically before expiry.
</Steps>

## Excluding a Service or Overriding a Label

Every app service with `ports:` gets the injected route. A service that publishes a port for
another protocol (a TCP game or database port, for instance) opts out with `traefik.enable=false`:

```yaml
# .dockflow/docker/docker-compose.yml
services:
  game:
    image: my-game
    ports:
      - "25000:25000"
    deploy:
      labels:
        - "traefik.enable=false"
```

A label the service sets itself always wins over the injected one, so the injected router can be
adjusted without being replaced:

```yaml
# .dockflow/docker/docker-compose.yml
services:
  app:
    image: my-app
    ports:
      - "3000:3000"
    deploy:
      labels:
        # serve another host with the router Dockflow names <stack>-<service>
        - "traefik.http.routers.my-app-production-app.rule=Host(`www.example.com`)"
```

<Callout type="warning">
  When several services of the stack get the injected route, they all answer on the same domain
  and Traefik sends each request to one of them. Dockflow warns when this happens: exclude the
  services that must not answer, or give them [routes of their own](#routing-a-service-on-its-own-domain).
</Callout>

## Routing a Service on Its Own Domain

`domains` gives the whole project one domain. `routes` sends a domain, or a path of one, to the
service of your choice, whether it is in `docker-compose.yml` or in `accessories.yml`:

```yaml
# .dockflow/config.yml
proxy:
  enabled: true
  email: admin@example.com
  routes:
    - service: panel               # HTTP on 4326
      domains:
        production: panel.example.com
        staging: panel.staging.example.com
      port: 4326
    - service: panel               # its WebSocket server, on 4327, same domain
      domains:
        production: panel.example.com
      path: /ws
      port: 4327
```

```yaml
# .dockflow/docker/accessories.yml
services:
  panel:
    image: my-panel
```

- `port` is the port the container listens on. Traefik reaches it over the `traefik-public`
  network, so the service does not publish it: leave `ports:` out. Without `port`, the route
  goes to the first port of `ports:`, else of `expose:`.
- `path` keeps only the requests whose path starts with it, and the path reaches the service
  unchanged. When two routes match a request, the one with the longer rule wins: above,
  `/ws` goes to 4327 and everything else to 4326. WebSocket connections need nothing more.
- A route is left out of the environments its `domains` does not list; a service none of whose
  routes lists the environment has no route there at all, and the deploy says so.
- A service listed in `routes` never gets the route on `domains`, in any environment. The other
  services with `ports:` still answer on `domains`; leave `domains` out to route only what
  `routes` lists.

Each route is a router named `<project>-<env>-<service>-route<n>`, where `n` is its position
among the routes of that service (from 1): add your own labels to it in `deploy.labels`, a
middleware for instance, and they win over the injected ones.

```yaml
# What Dockflow injects for the first route above, in production
deploy:
  labels:
    - "traefik.enable=true"
    - "traefik.docker.network=traefik-public"
    - "traefik.http.routers.my-app-production-panel-route1.rule=Host(`panel.example.com`)"
    - "traefik.http.routers.my-app-production-panel-route1.entrypoints=websecure"
    - "traefik.http.routers.my-app-production-panel-route1.service=my-app-production-panel-route1"
    - "traefik.http.services.my-app-production-panel-route1.loadbalancer.server.port=4326"
    - "traefik.http.routers.my-app-production-panel-route1.tls.certresolver=letsencrypt"
```

Before building anything, and on `--dry-run` too, `dockflow deploy` stops when a route names a
service that neither file has (or both have), when it cannot tell the port, when two routes share
a domain and path, or when a route without `path` takes the domain where services answer through
`domains`, or the dashboard's.

## Coexistence with Nginx

Traefik and the [nginx plugin](/en/configuration/plugins#nginx) do not know about each other.
Traefik is deployed as a Swarm service publishing ports 80 and 443, while the plugin installs a
vhost for the host's nginx and reloads it. A host nginx listening on port 80 and Traefik
publishing port 80 cannot both bind it.

Pick one: either drop the nginx plugin and route through Traefik labels, or leave
`proxy.enabled: false` and serve through nginx.

## Let's Encrypt Rate Limits

Let's Encrypt enforces [rate limits](https://letsencrypt.org/docs/rate-limits/). During testing, avoid triggering repeated certificate requests for the same domain. Errors are reported in Traefik logs:

```bash
# Check Traefik logs
dockflow exec production traefik "traefik logs"
# Or directly on the server
docker service logs traefik_traefik
```
