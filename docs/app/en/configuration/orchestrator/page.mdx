# Orchestrator

import { Callout } from 'nextra/components'

Dockflow deploys the same project to Docker Swarm (the default) or to k3s ([lightweight
Kubernetes](https://k3s.io)). The orchestrator changes how your project actually runs — and some features
differ between the two — but the same `config.yml`, `docker-compose.yml` and commands drive both.

## Minimal configuration

```yaml
# .dockflow/config.yml
orchestrator: k3s
```

<Callout type="info">
  When `orchestrator` is omitted it defaults to `swarm`; existing projects keep working unchanged.
</Callout>

<Callout type="warning">
  **Switching an existing environment's orchestrator is a redeploy into a new cluster** — releases are not
  migrated between orchestrators. **Breaking change**: `dockflow setup k3s <env>` now connects with a
  **bootstrap identity** (`--ssh-user`, default `root`, with `-k/--key` or `--password`) instead of the
  deploy key the previous `dockflow setup k3s` used, and it installs and manages the *whole* cluster.
  Kubernetes clusters created by a Dockflow version before this release (or set up by hand) are **not
  supported** and have no migration path — uninstall them and run `dockflow setup k3s <env>` fresh. See
  [Cluster setup](/en/configuration/kubernetes/setup) for the full procedure.
</Callout>

## Support matrix

| Feature | Swarm | k3s |
|---|---|---|
| Compose services | `docker stack deploy` | translated to Kubernetes objects ([support table](/en/configuration/kubernetes/compose-support)) |
| Accessories | separate stack `<project>-<env>-accessories` | same namespace as the app, distinguished by a role label |
| Published ports `H:C` | routing mesh on every node | ServiceLB LoadBalancer on every node |
| Services without ports | reachable by name | headless Service, reachable by name |
| Automatic HTTPS | Traefik service | Traefik Helm release in `dockflow-system` (pinned chart) |
| Failed update | reverted by Swarm | reverted by Dockflow (previous release's objects re-applied) |
| First deploy failure | Swarm rollback | workloads left in place for debugging |
| Release history, deploy lock | files on the manager | Secrets and a Lease in the cluster, shared by every server |
| Several managers | leader probe | any Ready server (`/readyz`); managers must be an odd count (1, 3, 5) |
| Local images | loaded on every node | imported into containerd on every node (pinned) |
| Registry | `docker login` + `--with-registry-auth` | `dockflow-registry` image pull Secret |
| `options.remote_build` | supported | refused |
| `dockflow exec --user` | supported | refused |
| Helm charts | not available | [`helm`](/en/configuration/helm) section |
| `dockflow volumes` | not available | supported |
| `dockflow prune --networks` | supported | refused |
| Backups | `docker exec` | `kubectl exec` streams and helper pods |
| Web dashboard | full | designed for Swarm; unsupported actions answer "not supported" |

## Refusals

An action a backend does not implement is refused before any remote work, with a message and a suggestion —
never a silent no-op:

| Capability | Message | Suggestion |
|---|---|---|
| `exec --user` | `<operation> is not supported with orchestrator: k3s: the Kubernetes exec API runs commands as the container user` | `Set user: in docker-compose.yml, or run: dockflow exec <env> <service> -- su -s /bin/sh <user> -c '<command>'` |
| `build --remote` / `options.remote_build` | `<operation> is not supported with orchestrator: k3s: k3s nodes run containerd only and ship no image builder` | `Build locally (remove options.remote_build) or push to a registry.` |
| `dockflow helm *` on Swarm | `<operation> requires orchestrator: k3s` | `Helm releases are only supported on Kubernetes.` |
| `dockflow volumes *` on Swarm | `<operation> is not supported with orchestrator: swarm` | `List Swarm volumes on a node with: dockflow ssh <env> then docker volume ls.` |
| `dockflow prune --networks` on k3s | `<operation> is not supported with orchestrator: k3s: the pod network is managed by the cluster` | (none) |

An API route hitting one of these returns HTTP 501 with `{success: false, message, suggestion}` instead of a
plain error.

## Data safety

| Command | Swarm volumes | k3s PersistentVolumeClaims |
|---|---|---|
| `dockflow deploy` (service removed) | kept | kept — never pruned |
| `dockflow stop` | kept | kept |
| `dockflow accessories remove` | kept | kept |
| `dockflow accessories remove --volumes` | deleted after a typed confirmation | deleted after a typed confirmation, one volume at a time (each PersistentVolume's reclaim policy is switched to `Delete` only once its claim is gone, and restored if the command stops) |
| `dockflow volumes rm` | not available | deleted after a typed confirmation; refused while mounted |
| Helm release removed from `config.yml` | n/a | kept running when it owns PersistentVolumeClaims (`dockflow helm uninstall <env> <name> --volumes` removes them explicitly) |
| web dashboard, API routes | never deletes volumes | never deletes volumes |

<Callout type="info">
  `-y` skips the prompt **and** the typed confirmation (for CI); without `-y` in a non-interactive shell the
  command refuses instead of proceeding silently. `dockflow volumes list` shows every volume's reclaim
  policy. See [Volumes & Data](/en/configuration/volumes) for the full protocol.
</Callout>

## Requirements

- k3s **server**: 2 CPU / 2 GB RAM. k3s **agent**: 1 CPU / 512 MB RAM.
- Ports, all restricted to the cluster's own nodes: TCP 6443 (agents to servers), TCP 10250 (every node to
  every node), UDP 8472 **or** UDP 51820/51821 (WireGuard, depending on the flannel backend), TCP 2379-2380
  (servers to servers, high availability only). 80/443 are opened to the public only when the [Automatic
  HTTPS Proxy](/en/configuration/proxy) is enabled.

<Callout type="warning">
  A published compose port bypasses host `ufw`/`firewalld` `INPUT` rules on both orchestrators — restrict
  it with `x-dockflow.lb_source_ranges` (k3s) or a provider firewall instead.
</Callout>
