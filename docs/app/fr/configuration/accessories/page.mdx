# Accessoires

import { Callout } from 'nextra/components'

Les accessoires sont des **services avec état** (bases de données, caches, files de messages, etc.) qui ont un cycle de vie séparé de votre application principale. Ils sont déployés une fois et restent intacts pendant les déploiements réguliers de l'app.

## Pourquoi des accessoires ?

<Callout type="warning">
  **Problème** : Si vous mettez votre base de données dans le `docker-compose.yml` principal, elle est redémarrée à chaque déploiement. Cela peut causer de la corruption de données ou des interruptions de service.
</Callout>

**Solution** : Les accessoires sont déployés comme une stack séparée (Swarm) ou un namespace séparé (k3s). Votre app peut être déployée 100 fois sans toucher à la base de données.

```
myapp-production              ← App principale (redéployée souvent)
myapp-production-accessories  ← Bases de données, Redis, etc. (déployés une fois)
```

## Configuration

Créez un fichier à `.dockflow/docker/accessories.yml` au format Docker Compose standard :

```yaml filename=".dockflow/docker/accessories.yml"
services:
  postgres:
    image: postgres:16-alpine
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: "{{ db_password }}"
      POSTGRES_DB: myapp
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app"]
      interval: 10s
      timeout: 5s
      retries: 5

  redis:
    image: redis:8-alpine
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data
    command: redis-server --appendonly yes
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  postgres_data:
  redis_data:
```

<Callout type="info">
  Les variables d'environnement peuvent être référencées avec la syntaxe de template : `{{ variable_name }}`
</Callout>

## Configuration de déploiement automatique

Dockflow injecte automatiquement une configuration de déploiement minimale pour chaque service accessoire :

```yaml
deploy:
  replicas: 1
  restart_policy:
    condition: on-failure
    delay: 5s
    max_attempts: 3
```

Cela garantit :
- **Une seule replica** par défaut (approprié pour les services avec état)
- **Redémarrage automatique** en cas d'échec avec backoff
- **Aucune mise à jour progressive** (vous contrôlez quand mettre à jour les bases de données)

Vous pouvez surcharger tout cela dans votre `accessories.yml`.

## Déploiement

Dockflow utilise une **détection de changement basée sur un hash** pour les accessoires. Cela signifie :

- Premier déploiement → les accessoires sont déployés automatiquement
- `accessories.yml` a changé → les accessoires sont redéployés automatiquement
- Aucun changement → les accessoires sont sautés (rapide)

### Déploiement automatique (défaut)

```bash
dockflow deploy production
# Déploie l'app
# Vérifie automatiquement le hash d'accessories.yml
# Déploie les accessoires uniquement si changement ou première fois
```

### Forcer le redéploiement des accessoires

```bash
dockflow deploy production --accessories  # Accessoires uniquement (forcé)
dockflow deploy production --all          # App + accessoires (forcé)
```

### Sauter la vérification des accessoires

```bash
dockflow deploy production --skip-accessories
# Déploie uniquement l'app, ignore complètement les accessoires
```

<Callout type="info">
  Le hash est stocké sur le serveur à `/var/lib/dockflow/accessories/{stack}/.hash`. Supprimez ce fichier pour forcer un redéploiement au prochain déploiement.
</Callout>

## Commandes de gestion

Toutes les commandes accessories utilisent SSH pour interagir avec les services en cours d'exécution.

### Lister les accessoires

```bash
dockflow accessories list production
# ou
dockflow acc ls production
```

Affiche tous les services accessoires avec leur statut et leurs replicas.

### Consulter les logs

```bash
dockflow accessories logs production           # Tous les accessoires
dockflow accessories logs production postgres  # Service spécifique
dockflow accessories logs production postgres -f  # Suivre
```

### Exécuter des commandes

```bash
dockflow accessories exec production postgres       # Ouvrir un shell
dockflow accessories exec production postgres psql  # Lancer psql
```

### Redémarrer des services

```bash
dockflow accessories restart production           # Tous
dockflow accessories restart production postgres  # Spécifique
```

### Arrêter des services

```bash
dockflow accessories stop production           # Passer tous à 0 replica
dockflow accessories stop production postgres  # Passer un service spécifique à 0 replica
```

<Callout type="info">
  Stop passe les services à 0 replica mais conserve les conteneurs et volumes. Utilisez `restart` pour les relancer.
</Callout>

### Supprimer les accessoires

```bash
dockflow accessories remove production           # Supprime la stack (conserve les volumes)
dockflow accessories remove production --volumes # Supprime la stack ET les volumes
```

<Callout type="error">
  Le flag `--volumes` supprime définitivement toutes les données. Il vous sera demandé de taper le nom de l'environnement pour confirmer.
</Callout>

## Bonnes pratiques

### 1. Toujours utiliser des volumes nommés

```yaml
volumes:
  - postgres_data:/var/lib/postgresql/data  # ✅ Volume nommé
  - ./data:/var/lib/postgresql/data         # ❌ Bind mount (perdu au redéploiement)
```

### 2. Épingler les versions d'images

```yaml
image: postgres:16-alpine  # ✅ Version spécifique
image: postgres:latest     # ❌ Mises à jour imprévisibles
```

### 3. Configurer les health checks

```yaml
healthcheck:
  test: ["CMD-SHELL", "pg_isready -U app"]
  interval: 10s
  timeout: 5s
  retries: 5
  start_period: 30s  # Laisser du temps pour le démarrage initial
```

### 4. Contraindre au nœud manager (optionnel)

Pour les déploiements mono-nœud, cela garantit que les données restent sur le même nœud :

```yaml
deploy:
  placement:
    constraints:
      - node.role == manager
```

## Connecter votre app

Votre application principale peut se connecter aux accessoires en utilisant le DNS interne de Docker :

```yaml filename=".dockflow/docker/docker-compose.yml"
services:
  app:
    image: myapp:latest
    environment:
      DATABASE_URL: postgres://app:password@postgres:5432/myapp
      REDIS_URL: redis://redis:6379
    networks:
      - default
      - accessories

networks:
  accessories:
    external: true
    name: myapp-production-accessories_default
```

<Callout type="warning">
  Assurez-vous de référencer le bon nom de réseau : `{project}-{env}-accessories_default`
</Callout>

<Callout type="info">
  **Protégez vos données** : Dockflow supporte la sauvegarde et la restauration automatisées pour les accessoires. Voir [Sauvegarde & Restauration](/fr/configuration/backup) pour les détails.
</Callout>
