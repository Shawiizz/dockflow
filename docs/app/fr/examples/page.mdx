## Setup minimal

Un service Node.js unique déployé sur un seul serveur.

### Structure du projet

<FileTree>
  <FileTree.Folder name=".dockflow" defaultOpen>
    <FileTree.Folder name="docker" defaultOpen>
      <FileTree.File name="docker-compose.yml" />
      <FileTree.File name="Dockerfile" />
    </FileTree.Folder>
    <FileTree.File name="config.yml" />
    <FileTree.File name="servers.yml" />
  </FileTree.Folder>
  <FileTree.File name=".env.dockflow" />
</FileTree>

### config.yml

```yaml
project_name: "my-app"
```

### servers.yml

```yaml
defaults:
  user: dockflow
  port: 22

servers:
  main_server:
    role: manager
    tags: [production]
    env:
      APP_PORT: "3000"
```

### docker-compose.yml

```yaml
services:
  app:
    image: my-app
    build:
      context: ../..
      dockerfile: Dockerfile
    ports:
      - "${APP_PORT}:3000"
    environment:
      ENV: ${ENV}
```

### Dockerfile

```dockerfile
FROM node:24-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build
CMD ["node", "dist/index.js"]
```

### Déployer

```bash
dockflow deploy production 1.0.0
```

## Full-stack avec accessoires

Une application frontend + backend avec PostgreSQL et Redis comme accessoires.

### Structure du projet

<FileTree>
  <FileTree.Folder name=".dockflow" defaultOpen>
    <FileTree.Folder name="docker" defaultOpen>
      <FileTree.File name="docker-compose.yml" />
      <FileTree.File name="accessories.yml" />
      <FileTree.File name="Dockerfile.frontend" />
      <FileTree.File name="Dockerfile.backend" />
    </FileTree.Folder>
    <FileTree.Folder name="hooks" defaultOpen>
      <FileTree.File name="post-deploy.sh" />
    </FileTree.Folder>
    <FileTree.File name="config.yml" />
    <FileTree.File name="servers.yml" />
  </FileTree.Folder>
</FileTree>

### config.yml

```yaml
project_name: "my-stack"

health_checks:
  enabled: true
  startup_delay: 15
  on_failure: rollback
  endpoints:
    - name: "API Health"
      url: "http://localhost:3000/health"
      expected_status: 200
      timeout: 30
      retries: 3
```

### servers.yml

```yaml
defaults:
  user: dockflow

servers:
  main_server:
    role: manager
    tags: [production]
    env:
      FRONTEND_PORT: "80"
      API_PORT: "3000"
      DB_HOST: "postgres"
      DB_PASSWORD: "secret"
      REDIS_URL: "redis://redis:6379"
```

### docker-compose.yml

```yaml
services:
  frontend:
    image: my-frontend
    build:
      context: ../..
      dockerfile: Dockerfile.frontend
    ports:
      - "${FRONTEND_PORT}:80"
    environment:
      API_URL: http://backend:3000
    networks:
      - frontend

  backend:
    image: my-backend
    build:
      context: ../..
      dockerfile: Dockerfile.backend
    environment:
      DB_HOST: ${DB_HOST}
      DB_PASSWORD: ${DB_PASSWORD}
      REDIS_URL: ${REDIS_URL}
    networks:
      - frontend
      - backend
    deploy:
      replicas: 2
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:3000/health"]
      interval: 30s
      timeout: 5s
      retries: 3

networks:
  frontend:
  backend:
```

### accessories.yml

```yaml
services:
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_PASSWORD: ${DB_PASSWORD}
      POSTGRES_DB: myapp
    volumes:
      - pgdata:/var/lib/postgresql/data
    networks:
      - backend

  redis:
    image: redis:8-alpine
    networks:
      - backend

volumes:
  pgdata:

networks:
  backend:
```

### Déployer

```bash
# Premier déploiement : déploie les accessoires, puis l'app
dockflow deploy production --all

# Déploiements suivants : app uniquement (accessoires auto-détectés)
dockflow deploy production 1.0.0

# Accéder à la base de données
dockflow acc exec production postgres "psql -U postgres myapp"
```

## Multi-hôtes avec registre

Un setup haute disponibilité avec plusieurs serveurs et un registre Docker.

### servers.yml

```yaml
defaults:
  user: dockflow

servers:
  manager_1:
    role: manager
    tags: [production]
    env:
      APP_PORT: "3000"
      DOMAIN: "app.example.com"

  worker_1:
    role: worker
    tags: [production]
    env:
      APP_PORT: "3000"

  worker_2:
    role: worker
    tags: [production]
    env:
      APP_PORT: "3000"
```

### config.yml

```yaml
project_name: "my-ha-app"

registry:
  enabled: true
  type: ghcr
  url: ghcr.io
  namespace: myorg
  username: "{{ current.env.registry_username }}"
  token: "{{ current.env.registry_token }}"
  additional_tags:
    - "latest"
    - "{branch}-latest"

health_checks:
  enabled: true
  startup_delay: 20
  on_failure: rollback
  endpoints:
    - name: "App Health"
      url: "http://localhost:3000/health"
      expected_status: 200
      retries: 5
```

### docker-compose.yml

```yaml
services:
  app:
    image: my-ha-app
    build:
      context: ../..
      dockerfile: Dockerfile
    ports:
      - "${APP_PORT}:3000"
    environment:
      ENV: ${ENV}
      DOMAIN: ${DOMAIN}
    deploy:
      replicas: 3
      placement:
        constraints:
          - node.role == worker
      resources:
        limits:
          cpus: "1.0"
          memory: 512M
```

### Secrets CI

```bash
# Une chaîne de connexion par serveur
PRODUCTION_MANAGER_1_CONNECTION=eyJob3N0Ijoi...
PRODUCTION_WORKER_1_CONNECTION=eyJob3N0Ijoi...
PRODUCTION_WORKER_2_CONNECTION=eyJob3N0Ijoi...

# Token du registre
REGISTRY_TOKEN=ghp_xxxx
```

### Setup

```bash
# 1. Setup de chaque serveur
dockflow setup root@manager-ip -k ~/.ssh/id_ed25519
dockflow setup root@worker1-ip -k ~/.ssh/id_ed25519
dockflow setup root@worker2-ip -k ~/.ssh/id_ed25519

# 2. Initialiser le cluster Swarm
dockflow setup swarm production

# 3. Déployer
dockflow deploy production 1.0.0
```

## Templates personnalisés

Utiliser des templates Nunjucks pour générer une configuration Nginx par serveur :

### config.yml

```yaml
project_name: "my-app"

templates:
  - src: "nginx/app.conf.njk"
    dest: "nginx/app.conf"
```

### nginx/app.conf.njk

```nginx
server {
    listen 80;
    server_name {{ current.env.domain }};

    location / {
        proxy_pass http://127.0.0.1:{{ current.env.app_port }};
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

Voir [Templates](/fr/configuration/templates) pour la référence complète du templating.

## Application avec HTTPS automatique

Un service unique déployé avec HTTPS automatique via Traefik. Aucune configuration Nginx requise.

### config.yml

```yaml
project_name: "my-app"

proxy:
  enabled: true
  email: admin@example.com
  domains:
    production: my-app.example.com
    staging: staging.my-app.example.com

health_checks:
  enabled: true
  on_failure: rollback
  endpoints:
    - name: "App"
      url: "https://my-app.example.com/health"
      expected_status: 200
```

### docker-compose.yml

```yaml
services:
  app:
    image: my-app
    build:
      context: ../..
      dockerfile: Dockerfile
    ports:
      - "3000:3000"
    environment:
      NODE_ENV: ${ENV}
```

Dockflow injecte automatiquement les labels de routage Traefik et connecte le service au réseau `traefik-public`. Aucune configuration manuelle de labels nécessaire.

### Déployer

```bash
dockflow deploy production 1.0.0
# → Traefik déployé sur le manager
# → Certificat obtenu depuis Let's Encrypt
# → https://my-app.example.com est en ligne
```

Voir [Proxy HTTPS automatique](/fr/configuration/proxy) pour toutes les options.
