# Commandes CLI

import { Callout, Tabs } from 'nextra/components'

Dockflow fournit un CLI complet pour gérer les déploiements et interagir avec les services en cours d'exécution.

## Installation

<Tabs items={['npm (tout OS)', 'npx (sans installation)', 'Linux / macOS', 'Windows']}>
  <Tabs.Tab>
    ```bash
    npm install -g @dockflow-tools/cli
    dockflow --version
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    Lancez n'importe quelle commande directement sans installer :

    ```bash
    npx @dockflow-tools/cli <command>
    ```

    <Callout type="info">
      Épinglez une version spécifique avec `npx @dockflow-tools/cli@1.2.3 <command>`.
    </Callout>
  </Tabs.Tab>
  <Tabs.Tab>
    ```bash
    curl -fsSL https://raw.githubusercontent.com/Shawiizz/dockflow/main/install.sh | bash
    dockflow --version
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    ```powershell
    irm https://raw.githubusercontent.com/Shawiizz/dockflow/main/install.ps1 | iex
    dockflow --version
    ```
  </Tabs.Tab>
</Tabs>

Le script détecte votre plateforme et architecture, télécharge le binaire, et l'ajoute à votre PATH.

<Callout type="info">
  Le binaire du CLI est autonome et ne nécessite aucune dépendance externe pour la plupart des commandes.
  Utilisez `dockflow setup` sur l'hôte Linux cible, ou `dockflow setup user@host` depuis n'importe quelle plateforme pour configurer un serveur distant via SSH.
</Callout>

Ces options sont disponibles sur toutes les commandes :

| Option | Description |
|--------|-------------|
| `--no-color` | Désactive la sortie colorée |
| `--verbose` | Active la sortie verbeuse |
| `-v, --version` | Affiche la version du CLI |

## Configuration de connexion

Les commandes app nécessitent des chaînes de connexion configurées comme secrets CI ou dans `.env.dockflow` pour le développement local :

```bash
# .env.dockflow (pour usage local du CLI)
PRODUCTION_MAIN_SERVER_CONNECTION=eyJob3N0Ijoi...  # JSON encodé en base64
STAGING_STAGING_SERVER_CONNECTION=eyJob3N0Ijoi...
```

La chaîne de connexion est générée par `dockflow setup` et contient :
- `host` : IP ou nom d'hôte du serveur
- `port` : Port SSH
- `user` : Utilisateur de déploiement
- `privateKey` : Clé privée SSH
- `password` : Mot de passe utilisateur (optionnel)

<Callout type="info">
  Les noms de serveur utilisent des underscores dans les secrets. Un serveur nommé `main_server` dans `servers.yml` utilise `MAIN_SERVER` dans le nom du secret.
</Callout>

<Callout type="info">
  Toutes les commandes qui acceptent un argument `<env>` supportent la **correspondance par préfixe** : tapez `pr` au lieu de `production`, `st` au lieu de `staging`, etc. Si le préfixe est ambigu, Dockflow listera les environnements correspondants.
</Callout>

## Commandes principales

### Deploy

```bash
dockflow deploy [env] [version]
```

Déploie l'application vers l'environnement spécifié. En CI, `env` et `version` sont tous deux auto-détectés depuis le tag git ou le nom de branche.

| Option | Description |
|--------|-------------|
| `--only <list>` | Liste de services séparés par des virgules à déployer |
| `--skip-build` | Saute la phase de build |
| `--force` | Force le déploiement même si verrouillé |
| `--accessories` | Déploie uniquement les accessoires (force le redéploiement) |
| `--all` | Déploie l'app + force le redéploiement des accessoires |
| `--skip-accessories` | Saute entièrement la vérification des accessoires |
| `--no-failover` | Désactive le failover multi-manager (utilise uniquement le premier manager) |
| `--dry-run` | Montre ce qui serait déployé sans exécuter |
| `--branch <name>` | Surcharge la branche git auto-détectée |
| `--debug` | Active la sortie de debug |

<Callout type="info">
  Par défaut, Dockflow vérifie si `accessories.yml` a changé et déploie automatiquement les accessoires si nécessaire. Utilisez `--skip-accessories` pour désactiver ce comportement.
</Callout>

```bash
dockflow deploy production 1.0.0          # Déploie une version spécifique
dockflow deploy staging                   # Version auto-générée
dockflow deploy production --accessories  # Force le redéploiement des accessoires uniquement
dockflow deploy production --all          # Déploie l'app + les accessoires
dockflow deploy production --dry-run      # Prévisualise sans exécuter
```

### Build

```bash
dockflow build [env]
```

Construit les images Docker localement sans déployer. En CI, l'environnement est auto-détecté depuis le tag git ou le nom de branche.

| Option | Description |
|--------|-------------|
| `--only <list>` | Liste de services séparés par des virgules à construire |
| `--push` | Pousse les images vers le registre après le build |
| `--skip-hooks` | Saute les hooks pre-build et post-build |
| `--branch <name>` | Surcharge la branche git auto-détectée |
| `--debug` | Active la sortie de debug |

```bash
dockflow build production                 # Construit tous les services
dockflow build production --only app      # Construit un service spécifique
dockflow build production --push          # Construit et pousse vers le registre
```

### Init

```bash
dockflow init [platform]
```

Initialise la structure du dossier `.dockflow/` avec les fichiers de configuration et le setup CI/CD.

```bash
dockflow init                 # Sélection interactive de la plateforme
dockflow init github          # GitHub Actions
dockflow init gitlab          # GitLab CI
```

### Config

```bash
dockflow config [subcommand]
```

Affiche et valide la configuration du projet.

| Sous-commande | Description |
|------------|-------------|
| `show` (défaut) | Affiche la configuration actuelle |
| `validate` (alias : `check`) | Valide les fichiers de config par rapport aux schémas |
| `path` | Affiche le chemin du répertoire de configuration |

La validation avertit aussi des clés inconnues : une clé que le schéma ne déclare pas est ignorée silencieusement au runtime (les fautes de frappe ne font jamais échouer un déploiement), donc `validate` signale chacune d'elles avec une suggestion "vouliez-vous dire" quand une correspondance proche existe — ex. `backup.retention` → `Did you mean "retention_count"?`.

| Option | S'applique à | Description |
|--------|-----------|-------------|
| `--json` | show, validate | Sortie en JSON |
| `--verbose` | validate | Affiche une sortie de validation détaillée |

```bash
dockflow config                   # Affiche la configuration
dockflow config validate          # Valide les fichiers de config
dockflow config check             # Identique à validate
dockflow config path              # Affiche le répertoire de config
```

### Validate

```bash
dockflow validate
```

Valide les fichiers de configuration `.dockflow` contre leurs schémas. S'exécute entièrement hors ligne — aucune connexion SSH, aucun serveur requis — ce qui en fait le moyen le plus rapide de vérifier une configuration avant de pousser.

Sont vérifiés `config.yml`, `servers.yml`, la présence du fichier compose, ainsi que les clés inconnues, signalées avec une suggestion. La commande échoue également sur les placeholders `${VAR}` de style shell présents dans le compose, que Dockflow ne substitue jamais (voir [Docker Compose](/fr/configuration/docker-compose)).

| Option | Description |
|--------|-------------|
| `--env <env>` | Vérifie aussi qu'un environnement précis existe dans `servers.yml` |

```bash
dockflow validate                 # Valide tous les fichiers de configuration
dockflow validate --env production
```

Sort en `0` si tout est valide, en `60` si une vérification échoue.

### UI

```bash
dockflow ui
```

Lance le dashboard WebUI de Dockflow pour la gestion visuelle des services, de la topologie, et des logs.

| Option | Description |
|--------|-------------|
| `-p, --port <port>` | Port d'écoute (défaut : 4200) |
| `--no-open` | N'ouvre pas le navigateur automatiquement |

### Completion

```bash
dockflow completion [shell]
```

Génère un script de complétion pour `bash`, `zsh` ou `fish`.

```bash
dockflow completion bash > /etc/bash_completion.d/dockflow
dockflow completion zsh  > "${fpath[1]}/_dockflow"
dockflow completion fish > ~/.config/fish/completions/dockflow.fish
```

## Commandes app

Ces commandes interagissent avec les services déployés via SSH. La plupart acceptent `-s, --server <name>` pour cibler un serveur spécifique (par défaut, le premier serveur de l'environnement).

### Logs

```bash
dockflow logs <env> [service]
```

Consulte les logs des services en cours d'exécution. Sur Swarm, seules les **replicas de tâche actuellement en cours d'exécution** sont streamées par défaut — les replicas terminées et crashées sont exclues pour éviter le bruit entrelacé d'échecs passés. Utilisez `--all-tasks` pour les inclure, ou `--pick` pour sélectionner une replica spécifique de manière interactive.

| Option | Description |
|--------|-------------|
| `-f, --follow` | Suit la sortie des logs |
| `-n, --tail <lines>` | Nombre de lignes à afficher (défaut : 100) |
| `-T, --timestamps` | Affiche les timestamps |
| `--since <time>` | Affiche les logs depuis un timestamp (ex. `1h`, `2024-01-01`) |
| `-s, --server <name>` | Serveur cible |
| `-a, --all-tasks` | Inclut les logs des replicas de tâche terminées/historiques (Swarm uniquement) |
| `--pick` | Sélectionne interactivement quelle replica de tâche suivre (Swarm uniquement) |

```bash
dockflow logs production                 # Tous les services, replicas en cours uniquement
dockflow logs production app -f          # Suit un service spécifique
dockflow logs production app -n 500      # Les 500 dernières lignes
dockflow logs production --since 1h      # La dernière heure
dockflow logs production app --all-tasks # Inclut les replicas crashées/anciennes
dockflow logs production app --pick      # Choisit une replica dans une liste
```

<Callout type="info">
Le sélecteur `--pick` liste chaque tâche (en cours + historique) avec son état actuel, son index de replica, son nœud, et tout message d'erreur — utile pour comprendre pourquoi une replica spécifique a crashé.
</Callout>

### Exec

```bash
dockflow exec <env> <service> [command...]
```

Exécute une commande à l'intérieur d'un conteneur en cours d'exécution (défaut : bash).

| Option | Description |
|--------|-------------|
| `-s, --server <name>` | Serveur cible |
| `-u, --user <user>` | S'exécute en tant qu'utilisateur spécifié |
| `-w, --workdir <dir>` | Répertoire de travail dans le conteneur |

```bash
dockflow exec production app bash          # Shell interactif
dockflow exec production app "ls -la"      # Lance une commande
dockflow exec production db "psql -U user" # Accès base de données
```

### Bash

```bash

```

| Option | Description |
|--------|-------------|
| `-s, --server <name>` | Serveur cible |
| `--sh` | Utilise sh au lieu de bash |


```bash
dockflow audit <env>
```

| Option | Description |
|--------|-------------|

| `--json` | Sortie en JSON |

### History Sync

```bash
dockflow history-sync <env>
```

Synchronise l'historique de déploiement entre tous les nœuds du cluster. Chaque nœud enregistre les déploiements localement : après un basculement, ou si un nœud était injoignable pendant un déploiement, les historiques peuvent diverger. Cette commande les réconcilie.

| Option | Description |
|--------|-------------|
| `--debug` | Active la sortie de débogage |

```bash
dockflow history-sync production
```

| Option | Description |

```bash

```

| Option | Description |

### Prune

```bash
dockflow prune <env>
```

Supprime les ressources Docker inutilisées du serveur.

| Option | Description |
|--------|-------------|
| `-a, --all` | Supprime toutes les images inutilisées, pas seulement les dangling |
| `--images` | Purge uniquement les images |
| `--containers` | Purge uniquement les conteneurs |
| `--volumes` | Purge uniquement les volumes |
| `--networks` | Purge uniquement les réseaux |
| `-y, --yes` | Sans confirmation |
| `-s, --server <name>` | Serveur cible |

<Callout type="warning">
  L'option `--volumes` supprime définitivement les données stockées dans les volumes Docker non attachés.
</Callout>

```bash
dockflow prune production              # Purge tout (avec confirmation)
dockflow prune production -y           # Sans confirmation
dockflow prune production --images -a  # Toutes les images inutilisées
```

## Commandes backup

Sauvegarde et restauration des bases de données des accessoires. Voir [Backup & Restore](/fr/configuration/backup) pour la configuration par service.

### Créer une sauvegarde

```bash
dockflow backup create <env> [service]
```

Crée une sauvegarde d'un service ou d'une base d'accessoire. Sans nom de service, sauvegarde tous les accessoires configurés.

| Option | Description |
|--------|-------------|
| `-j, --json` | Sortie des métadonnées au format JSON |
| `-s, --server <name>` | Serveur ciblé (par défaut le premier de l'environnement) |

```bash
dockflow backup create production            # Tous les accessoires configurés
dockflow backup create production postgres   # Un seul service
dockflow bak create production postgres      # `bak` est un alias
```

### Lister les sauvegardes

```bash
dockflow backup list <env> [service]
```

Liste les sauvegardes disponibles.

| Option | Description |
|--------|-------------|
| `-j, --json` | Sortie au format JSON |
| `-s, --server <name>` | Serveur ciblé |

```bash
dockflow backup list production
dockflow backup ls production postgres       # `ls` est un alias
```

### Restaurer une sauvegarde

```bash
dockflow backup restore <env> [service]
```

Restaure un service ou une base d'accessoire depuis une sauvegarde. Restaure la plus récente sauf si `--from` est fourni.

| Option | Description |
|--------|-------------|
| `--from <id>` | Identifiant de sauvegarde ou préfixe de date (par défaut : la plus récente) |
| `-y, --yes` | Ignore la demande de confirmation |
| `-s, --server <name>` | Serveur ciblé |

```bash
dockflow backup restore production postgres
dockflow backup restore production postgres --from 2026-08-29
```

<Callout type="warning">
  Une restauration écrase la base actuelle. Une confirmation est demandée sauf si `--yes` est passé.
</Callout>

### Purger les sauvegardes

```bash
dockflow backup prune <env> [service]
```

Supprime les anciennes sauvegardes en conservant les N plus récentes par service.

| Option | Description |
|--------|-------------|
| `--keep <n>` | Nombre de sauvegardes conservées par service (par défaut : `retention_count` de la config, sinon 10) |
| `-y, --yes` | Ignore la demande de confirmation |
| `-s, --server <name>` | Serveur ciblé |

```bash
dockflow backup prune production --keep 5
```

## Commandes de setup

Configure les serveurs pour le déploiement. Doit être lancé sur un hôte Linux, ou utilisez `setup user@host` pour les serveurs distants.

### Setup interactif

```bash
dockflow setup
```

Lance l'assistant de setup interactif. Sur Windows/macOS, propose de se connecter à un serveur Linux via SSH.

### Setup distant

```bash
dockflow setup user@host[:port]
```

Lance le setup sur un serveur Linux distant depuis n'importe quelle plateforme.

| Option | Description |
|--------|-------------|
| `-k, --key <path>` | Chemin vers la clé privée SSH |
| `--password <password>` | Mot de passe SSH |
| `--connection <string>` | Utilise une chaîne de connexion Dockflow existante |

```bash
dockflow setup root@192.168.1.10 -k ~/.ssh/id_ed25519
dockflow setup root@192.168.1.10:2222 -k ~/.ssh/id_ed25519
dockflow setup --connection "eyJob3N0Ijoi..."
```

### Setup non-interactif

```bash
dockflow setup --host <ip> --user <name> --password <pwd> --generate-key
```

Configure un serveur sans invites (Linux uniquement, doit s'exécuter sur l'hôte cible). Passez les flags directement plutôt que d'utiliser l'assistant interactif.

| Option | Description |
|--------|-------------|
| `--host <host>` | IP/nom d'hôte public pour la chaîne de connexion |
| `--port <port>` | Port SSH (défaut : 22) |
| `--user <user>` | Nom d'utilisateur de déploiement |
| `--password <password>` | Mot de passe pour le nouvel utilisateur ou sudo |
| `--ssh-key <path>` | Chemin vers une clé privée SSH existante |
| `--generate-key` | Génère une nouvelle clé SSH |
| `--deploy-password <pw>` | Mot de passe pour l'utilisateur de déploiement créé à distance (distant, avec `--user`) |
| `--skip-docker-install` | Saute l'installation de Docker |
| `--orchestrator <type>` | `swarm` (défaut) ou `k3s` — k3s saute l'installation de Docker |
| `--portainer` | Installe Portainer |
| `--portainer-port <port>` | Port HTTP de Portainer (défaut : 9000) |
| `--portainer-password <pw>` | Mot de passe admin de Portainer |
| `--portainer-domain <domain>` | Nom de domaine de Portainer |
| `-y, --yes` | Sans confirmations |

### Initialiser Swarm

```bash
dockflow setup swarm <env>
```

Initialise un cluster Docker Swarm pour un environnement. Rattache tous les serveurs configurés dans `servers.yml` au Swarm.

### Initialiser k3s

```bash
dockflow setup k3s <env>
```

Installe et configure k3s sur le serveur cible pour un environnement.

### Vérifier les dépendances

```bash
dockflow setup check
```

Vérifie que toutes les dépendances requises sont installées.

### Obtenir la chaîne de connexion

```bash
dockflow setup connection
```

Affiche la chaîne de connexion pour un utilisateur de déploiement existant.

| Option | Description |
|--------|-------------|
| `--host <host>` | IP/nom d'hôte du serveur |
| `--port <port>` | Port SSH (défaut : 22) |
| `--user <user>` | Nom d'utilisateur de déploiement |
| `--key <path>` | Chemin vers la clé privée SSH |

## Prérequis

- `.env.dockflow` avec les chaînes de connexion (ou secrets CI)
- `.dockflow/config.yml` avec `project_name`

**Pour les commandes de setup (sur l'hôte Linux cible) :**
- Accès root (le setup local doit s'exécuter en root ; le setup distant s'élève automatiquement)
- SSH (`ssh`, `ssh-keygen`)
- curl (télécharge le script d'installation de Docker)

Les dépendances manquantes sont installées automatiquement pendant le setup.

## Exemple de workflow complet

```bash
# 1. Setup du serveur
dockflow setup root@192.168.1.10 -k ~/.ssh/id_ed25519

# 2. Sauvegarder la chaîne de connexion
echo "PRODUCTION_MAIN_SERVER_CONNECTION=..." > .env.dockflow

# 3. Initialiser le projet
dockflow init github

# 4. Valider la configuration
dockflow config validate

# 5. Build en local (optionnel)
dockflow build production

# 6. Déployer
dockflow deploy production 1.0.0

# 7. Surveiller
dockflow logs production -f
dockflow details production
dockflow ps production

# 8. Vérifier la version et l'audit
dockflow version production
dockflow audit production

# 9. Dépanner
dockflow diagnose production
dockflow bash production app
dockflow ssh production

# 10. Scaler
dockflow scale production app 3

# 11. Rollback si nécessaire
dockflow rollback production app

# 12. Gérer les accessoires
dockflow acc logs production postgres -f
dockflow acc exec production postgres psql

# 13. Nettoyage
dockflow prune production --images -a
```
