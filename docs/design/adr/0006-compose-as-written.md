# ADR-0006: Compose as written plus `dockflow.yml`; no template engine

- Status: Accepted
- Date: 2026-10-25

## Context

Dockflow 1.x uses five kinds of files (`config.yml`, `servers.yml`, a flat `dockflow.yml` alternative, `.env.dockflow`, compose files). It renders every file under `.dockflow/` with Nunjucks, which breaks Go templates, Prometheus rules and bash, and renders an undefined variable as an empty string. Values per environment can be set four different ways. The compose files are not valid Compose until rendered.

## Decision

A project has:

1. **Its Compose files, as written.** They stay valid for `docker compose up` on a laptop.
   - Variation between environments uses Compose's own mechanisms: several files merged in order (`compose.yml` then `compose.prod.yml`), `${VAR}` interpolation and profiles.
   - Dockflow's per-service settings live in `x-dockflow` keys, which Compose ignores.
2. **One `dockflow.yml`**: the app name, its environments, the managers of each environment, interpolation variables, the secrets file, the registry, the hooks.
3. **One encrypted secrets file per environment**, optional ([ADR-0012](0012-secrets-sops.md)).

There is no template engine:

- Interpolation is Compose's (`${VAR}`, `${VAR:-default}`, `${VAR:?message}`), performed by compose-go.
- The values come from Dockflow's built-in variables, then the environment's `vars`, then its secrets. The process environment is never read, so a deploy does not depend on what happens to be exported on the machine that runs it.
- A variable that is not defined and has no default is an error, even without `:?`.
- Files outside Compose are never rendered.

`dockflow.yml` itself has no interpolation. Its format is versioned (`version: 1`), unknown keys are errors, and it is fully described in the [configuration spec](../spec/config-v1.md).

## Consequences

- One way to vary a value per environment: `vars` and Compose override files.
- A project's Compose works locally with no Dockflow involved.
- Templated configuration files (an nginx config, for example) are no longer generated by Dockflow. They are either built into images or delivered as Compose `configs:` with interpolated content, which Compose already supports.
- No silent empty values: a typo in a variable name fails `dockflow plan`.

## Alternatives considered

- **Everything in `compose.yml` under a top-level `x-dockflow`.** Rejected: managers and environments are deployment data, not application data, and they would make the file unusable as is for local development by teammates.
- **A configuration language (TypeScript, CUE, Pkl).** Rejected: the TUI, the MCP server and linters need to read and check the configuration as data.
- **Keeping Nunjucks for opt-in files.** Rejected: Compose `configs:` with interpolation covers the real use cases.
