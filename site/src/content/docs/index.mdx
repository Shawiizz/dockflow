## One command, every time

`dockflow deploy` builds what changed, shows the plan, starts the new containers next to the old ones, checks them, and moves the traffic in one step. If anything fails, the previous release keeps serving.

## Why Dockflow

<CardGrid>
	<Card title="Compose, as written" icon="document">
		Your `compose.yml` is the source of truth. Dockflow reads it with the same loader as Docker Compose and adds only what a deploy needs, under `x-dockflow`.
	</Card>
	<Card title="Zero downtime" icon="random">
		Routed services switch in one step once the new containers are healthy, and the old ones drain. It is tested under load: no failed request during a deploy or a rollback.
	</Card>
	<Card title="A plan before every change" icon="list-format">
		`dockflow plan` shows exactly what a deploy would create, update or remove. A deploy touches only what changed; an unchanged service keeps its containers.
	</Card>
	<Card title="Rollbacks that finish" icon="up-arrow">
		Every deploy is a release. A failed deploy rolls back on its own, and `dockflow rollback` restores an earlier release with its images and files, without a rebuild.
	</Card>
	<Card title="No registry to run" icon="cloud-download">
		Images go to a registry on the server, through an SSH tunnel, and only the layers it lacks are sent. An external registry works too.
	</Card>
	<Card title="Only Docker on the server" icon="laptop">
		One binary on your side. On the server, Dockflow's switch, registry and short-lived agent are containers, driven through the Docker Engine API.
	</Card>
</CardGrid>

## What it looks like

<Tabs>
<TabItem label="dockflow.yml">

```yaml
# dockflow.yml
version: 1
app: shop

health:
  endpoints:
    - url: https://shop.example.com/

environments:
  production:
    vars:
      DOMAIN: shop.example.com
```

</TabItem>
<TabItem label="compose.yml">

```yaml
# compose.yml
services:
  web:
    build: .
    environment:
      DATABASE_URL: postgres://shop:${DB_PASSWORD}@db/shop
    deploy:
      replicas: 2
    x-dockflow:
      routes:
        - domains: ["${DOMAIN}"]
          port: 3000
      health:
        http: { path: /healthz }
  db:
    image: postgres:17
    volumes: [pgdata:/var/lib/postgresql/data]
    x-dockflow:
      stateful: true
volumes:
  pgdata:
```

</TabItem>
<TabItem label="GitHub Actions">

```yaml
# .github/workflows/deploy.yml
on:
  push:
    tags: ['*']        # 1.8.0 deploys to production
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: curl -fsSL https://raw.githubusercontent.com/Shawiizz/dockflow/main/install.sh | sh
      - run: dockflow deploy
        env:
          PRODUCTION_CONNECTION: ${{ secrets.PRODUCTION_CONNECTION }}
          PRODUCTION_DB_PASSWORD: ${{ secrets.PRODUCTION_DB_PASSWORD }}
```

</TabItem>
