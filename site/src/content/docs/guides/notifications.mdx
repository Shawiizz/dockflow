`notify:` lists webhooks that Dockflow calls when a run that changes an environment ends: a deploy, a rollback, a restart. Each call is an HTTP `POST` with a JSON body, signed with HMAC-SHA256 when you give it a secret. Use it to post to a chat, open an incident, or record deploys in another system.

## Example

```yaml
# dockflow.yml
version: 1
app: shop
notify:
  - url: https://hooks.example.com/dockflow
    secret: ${WEBHOOK_SECRET}
  - url: https://alerts.example.com/hooks/deploys
    on: [failure]
    headers:
      Authorization: Bearer ${ALERTS_TOKEN}
    timeout: 5s
environments:
  production: {}
```

The first webhook receives every outcome, signed with the `WEBHOOK_SECRET` secret (`PRODUCTION_WEBHOOK_SECRET` in CI for `production`). The second receives failures only, with an extra header.

## Options

| Key | Type | Default | Description |
|---|---|---|---|
| `url` | string | required | An `http` or `https` URL |
| `on` | list | both | `success`, `failure`, or both: the statuses this webhook receives |
| `secret` | string | none | Signs the body: the request carries `X-Dockflow-Signature` |
| `headers` | map | none | Extra request headers |
| `timeout` | duration | `10s` | How long to wait for the response |

String values are interpolated like the rest of `dockflow.yml`, so `${WEBHOOK_SECRET}` reads a secret, and a missing one stops the command with exit code 3. Secret values are masked wherever Dockflow prints them. `notify:` can also be set inside an environment, where it replaces the top-level list for that environment.

## When webhooks fire

A webhook fires at the end of a run of the agent on the server, for these operations: `deploy`, `rollback`, `restart`, `stop`, `scale` and `destroy`. It does not fire:

- when the run changed nothing (a deploy whose plan is empty);
- when the run could not start because another run holds the lock;
- for failures before the agent runs: a failed build, a fatal `before_*` local or `host` [hook](/guides/hooks/), an invalid configuration;
- for read commands (`status`, `plan`, `logs`…) and for `prune`.

A deploy whose local `after_deploy` hook fails and triggers a rollback sends two webhooks: one for the deploy (`success`), one for the rollback run that follows.

Webhooks are sent by the CLI, after the agent reports the result. If the CLI is stopped before that, they are not sent.

## Request

```http
POST /dockflow HTTP/1.1
Content-Type: application/json
User-Agent: dockflow
X-Dockflow-Event: run.finished
X-Dockflow-Signature: sha256=5d1e9c…
```

Your `headers` are added after these, and replace one of them when they share a name.

### Payload

```json
{
  "event": "run.finished",
  "app": "shop",
  "env": "production",
  "server": "main",
  "op": "deploy",
  "run": "01JBF3K9Q2M8XW4T6Y7Z1N5R0C",
  "version": "1.4.0",
  "release": 42,
  "outcome": "rolled_back",
  "status": "failure",
  "exit_code": 8,
  "duration_ms": 73120,
  "error": "service web is unhealthy: …",
  "at": "2026-10-26T14:03:12.481Z"
}
```

| Field | Description |
|---|---|
| `event` | Always `run.finished` |
| `app`, `env` | The app and the environment |
| `server` | The server's name (`main` unless the environment names it) |
| `op` | `deploy`, `rollback`, `restart`, `stop`, `scale` or `destroy` |
| `run` | The run's ID, for `dockflow attach <env> <run-id>` |
| `version` | The version label the CLI computed for the run (`--version`, the CI tag, or the commit). For a deploy, the release's version. For other operations it is that of the local checkout, not necessarily what runs: `dockflow releases` shows that |
| `release` | The release number the run created; absent when it created none |
| `outcome` | `success`, `rolled_back`, `failed`, `cancelled`, `lock_lost` or `hook_failed` (see [events](/reference/events/)) |
| `status` | `success` when `outcome` is `success`, `failure` otherwise. This is what `on` filters on |
| `exit_code` | The CLI's [exit code](/reference/exit-codes/) for this outcome |
| `duration_ms` | How long the run took |
| `error` | The error message, with secret values masked; absent on success |
| `at` | When the webhook was sent, in UTC |

## Verifying the signature

With a `secret`, the `X-Dockflow-Signature` header is `sha256=` followed by the hex HMAC-SHA256 of the raw request body, keyed with the secret. To verify it:

1. Read the body as bytes, before any JSON parsing.
2. Compute the HMAC-SHA256 of those bytes with the same secret.
3. Compare it with the header in constant time, and reject the request when they differ.

<Tabs>
<TabItem label="Node.js">

```js
// server.mjs
import { createServer } from 'node:http';
import { createHmac, timingSafeEqual } from 'node:crypto';

const secret = process.env.WEBHOOK_SECRET;

function valid(body, header) {
  const expected = 'sha256=' + createHmac('sha256', secret).update(body).digest('hex');
  const a = Buffer.from(expected);
  const b = Buffer.from(header ?? '');
  return a.length === b.length && timingSafeEqual(a, b);
}

createServer((req, res) => {
  const chunks = [];
  req.on('data', (c) => chunks.push(c));
  req.on('end', () => {
    const body = Buffer.concat(chunks);
    if (!valid(body, req.headers['x-dockflow-signature'])) {
      res.writeHead(401).end();
      return;
    }
    const p = JSON.parse(body);
    console.log(`${p.app} ${p.env}: ${p.op} ${p.status} (${p.version})`);
    res.writeHead(204).end();
  });
}).listen(8000);
```

</TabItem>
<TabItem label="Python">

```python
# verify.py
import hashlib
import hmac


def valid(secret: str, body: bytes, header: str | None) -> bool:
    expected = "sha256=" + hmac.new(secret.encode(), body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, header or "")
```

Call it with the raw body, for example `request.get_data()` in Flask or `await request.body()` in FastAPI, and `request.headers.get("X-Dockflow-Signature")`.

</TabItem>
<TabItem label="Go">

```go
// main.go
package main

import (
	"crypto/hmac"
	"crypto/sha256"
	"encoding/hex"
	"encoding/json"
	"io"
	"log"
	"net/http"
	"os"
	"strings"
)

func valid(secret string, body []byte, header string) bool {
	got, ok := strings.CutPrefix(header, "sha256=")
	if !ok {
		return false
	}
	sig, err := hex.DecodeString(got)
	if err != nil {
		return false
	}
	m := hmac.New(sha256.New, []byte(secret))
	m.Write(body)
	return hmac.Equal(sig, m.Sum(nil))
}

func main() {
	secret := os.Getenv("WEBHOOK_SECRET")
	http.HandleFunc("/dockflow", func(w http.ResponseWriter, r *http.Request) {
		body, err := io.ReadAll(io.LimitReader(r.Body, 1<<20))
		if err != nil || !valid(secret, body, r.Header.Get("X-Dockflow-Signature")) {
			http.Error(w, "bad signature", http.StatusUnauthorized)
			return
		}
		var p struct {
			App, Env, Op, Status, Version string
		}
		if err := json.Unmarshal(body, &p); err != nil {
			http.Error(w, "bad payload", http.StatusBadRequest)
			return
		}
		log.Printf("%s %s: %s %s (%s)", p.App, p.Env, p.Op, p.Status, p.Version)
		w.WriteHeader(http.StatusNoContent)
	})
	log.Fatal(http.ListenAndServe(":8000", nil))
}
```

## Failures

A webhook that cannot be reached, times out, or answers with a status of 300 or more is reported as a warning (`notify.failed` in `--json` output). It never changes the outcome or the exit code of the run, and it is not retried. Each webhook is called once per run, one after the other.
